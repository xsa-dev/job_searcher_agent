# Ключевые возможности Multi-Agent System

**Версия**: 2.0.1  
**Дата**: 2025-11-07

---

## 🎯 Основные возможности

### 1. Мультиагентная архитектура ✅

**4 специализированных агента:**
- **Supervisor** - контроллер и маршрутизатор
- **Planner** - создание и адаптация планов
- **Browser Agent** - автоматизация браузера (ReAct loop)
- **Cover Letter Agent** - генерация писем

### 2. Переиспользование планов ✅ NEW!

**Экономия времени и токенов:**
- Planner проверяет последнюю сессию
- Если есть план - использует его
- Экономия: ~10-15 секунд + токены LLM

**Как работает:**
```
Запуск → Загрузка истории → Проверка последней сессии
                                    ↓
                         Есть план? → ДА → Использовать
                                    ↓
                                   НЕТ → Создать новый
```

**Логи:**
```
🔍 Проверка последней сессии: 2025-11-07T23:36:31
   План: есть (195 символов)
   Шаги: 46 шагов
♻️ Найден план из предыдущей сессии
   Откликов было: 0/0
   Переиспользуем план для продолжения работы
✅ План загружен из истории: 46 шагов
```

### 3. Асинхронное выполнение ✅

**Все операции асинхронные:**
- LLM вызовы через `ainvoke()`
- MCP инструменты через `ainvoke()`
- ReAct цикл с до 10 итераций

### 4. Сохранение истории ✅

**Автоматическое сохранение:**
- Каждая сессия → JSON файл
- План, шаги, вакансии, письма
- Статистика выполнения

**Структура:**
```json
{
  "session_id": "...",
  "timestamp": "2025-11-07T23:36:31",
  "plan": "...",
  "plan_steps": [...],
  "vacancies_processed": [...],
  "statistics": {
    "total_applied": 0,
    "total_vacancies_found": 0
  }
}
```

### 5. Избегание дубликатов ✅

**Проверка откликов:**
- Загрузка последних 50 сессий
- Проверка URL вакансий
- Автоматический пропуск дубликатов

### 6. Адаптивное планирование ✅

**Учет истории:**
- Анализ последних 5 сессий
- Успешные паттерны
- Средний score откликов

### 7. Персонализированные письма ✅

**Генерация:**
- Уникальное письмо для каждой вакансии
- Учет требований вакансии
- Примеры успешных писем из истории
- 500-1000 символов

### 8. Автоматическая проверка авторизации ✅ NEW!

**Умная проверка:**
- Browser Agent анализирует содержимое страницы
- Определяет наличие элементов профиля
- Пропускает логин если уже авторизован
- Экономия времени при повторных запусках

**Признаки авторизации (пункты меню HH):**
- ✅ "Резюме" - пункт меню
- ✅ "Профиль" - пункт меню
- ✅ "Отклики" - пункт меню
- ✅ "Сообщения" - иконка сообщений
- ✅ "Уведомления" - иконка нотификаций

**Логика проверки:**
- Найдено 2+ элемента + нет кнопки "Войти" = авторизован
- Найдено 3+ элемента = авторизован (даже если есть "Войти")

**Логи:**
```
🔍 Проверка статуса авторизации...
   Найдено элементов авторизованного меню: 4
   Найденные элементы: резюме, профиль, отклики, сообщения
   Признаков НЕавторизации: 0
✅ Пользователь уже авторизован!
➡️ Переход к поиску вакансий
```

## 📊 Performance

### Время выполнения

| Операция | Без оптимизаций | С оптимизациями |
|----------|----------------|----------------|
| Planner | 10-15 сек | **0 сек** ✅ (переиспользование) |
| Browser (логин) | 10-20 сек | **0 сек** ✅ (если уже авторизован) |
| Browser (поиск) | 15-30 сек | 15-30 сек |
| Cover Letter | 10-15 сек | 10-15 сек |
| Browser (отклик) | 10-20 сек | 10-20 сек |

**Экономия на запуске:** ~20-35 секунд (план + авторизация)

### Токены LLM

| Операция | Токены |
|----------|--------|
| Planner (создание) | ~1000-1500 |
| Planner (переиспользование) | **0** ✅ |
| Cover Letter | ~800-1200 |
| Browser Agent | ~500-800 |

**Экономия токенов:** ~1000-1500 на запуск

## 🔧 Настройка

### Включение/отключение переиспользования

По умолчанию **включено**. Для отключения:

```python
# В planner_node установите флаг
state["plan_needs_update"] = True  # Принудительно создать новый план
```

### Настройка глубины истории

В `_get_last_unfinished_plan`:
```python
# Проверять последние N сессий
for session in sessions[-3:]:  # ← изменить число
```

## 🚀 Использование

### Обычный запуск

```bash
uv run python main.py
```

**Что происходит:**
1. Загрузка истории
2. Проверка последней сессии
3. Если есть план → использовать
4. Если нет → создать новый
5. Выполнение плана

### Принудительное создание нового плана

```python
# В main.py
initial_state = create_initial_state(...)
initial_state["plan_needs_update"] = True  # Создать новый план
```
