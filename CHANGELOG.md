# Changelog

Все значимые изменения в проекте документируются в этом файле.

## [2.1.0] - 2025-11-08

### 🔄 Major Changes

- **Миграция с BrowserMCP на Playwright MCP**:
  - Заменен `@browsermcp/mcp@0.1.3` на `@playwright/mcp@latest` (официальный Playwright MCP)
  - Обновлены все инструменты браузера:
    - `browser_navigate` → `Playwright_navigate`
    - `browser_snapshot` → `playwright_get_visible_text` / `playwright_get_visible_html`
    - `browser_click` → `Playwright_click`
    - `browser_type` → `Playwright_fill`
    - `browser_tabs` → `playwright_click_and_switch_tab`
  - Обновлены промпты агентов для новых инструментов
  - Улучшенная стабильность и расширенные возможности
  - Поддержка iframe, загрузки файлов, генерации тестов
  - Обновлена документация: PLAYWRIGHT_SETUP.md

### 🐛 Bug Fixes

- **Исправлена ошибка HTTP 400 Bad Request от Foundation Model API**:
  - Добавлены обязательные параметры: `max_tokens`, `top_p`, `presence_penalty`
  - Исправлена конфигурация `ChatOpenAI` для совместимости с Foundation Models API
  - Убран `model_kwargs` для параметров, поддерживаемых напрямую
- **Исправлена проблема с `@executeautomation/playwright-mcp-server`**:
  - Сервер крашился при запуске ("Shutdown signal received")
  - Заменен на официальный `@playwright/mcp@latest` от Microsoft
  - Стабильная работа с 21 инструментом
- Добавлена обработка ошибок "Shutdown signal received" и "Invalid JSON" от MCP
- Расширен список игнорируемых ошибок при закрытии MCP сессии (BrokenResourceError, ValidationError)
- Улучшена стабильность при завершении работы с браузером

### 📚 Documentation

- Создан новый PLAYWRIGHT_SETUP.md с полным описанием API
- Удалены устаревшие документы: BROWSERMCP_PATCH.md, FIXES_SUMMARY.md, BROWSERMCP_SETUP.md
- Обновлены все README и guides с новыми инструментами

## [2.0.2] - 2025-11-08

- **Поддержка работы с вкладками браузера**:
  - Добавлен инструмент browser_tabs в промпт
  - Инструкции по переключению между вкладками
  - Автоматическое закрытие вкладок после отклика
  - Возврат на главную вкладку

### 🔄 Changed

- Обновлены инструкции Browser Agent для работы с новыми вкладками
- Улучшена обработка статуса "already_applied"

## [2.0.1] - 2025-11-07

### ✨ Added

- **Переиспользование планов из истории**:
  - Planner теперь проверяет последнюю сессию на наличие плана
  - Если план найден - использует его вместо создания нового
  - Экономия времени и токенов LLM (~10-15 секунд на запуск)
  - Детальное логирование процесса поиска плана

- **Автоматическая проверка авторизации**:
  - Browser Agent проверяет статус авторизации перед действиями
  - Анализ специфичных элементов меню HH: "Резюме", "Профиль", "Отклики", иконки сообщений/уведомлений
  - Двухуровневая логика: 2+ элемента без "Войти" ИЛИ 3+ элемента
  - Пропуск логина если пользователь уже авторизован
  - Экономия времени (~10-18 секунд) при повторных запусках
  - Детальное логирование найденных элементов

### 🔧 Fixed

- **Browser Agent теперь реально выполняет действия**:
  - Исправлена ошибка `StructuredTool does not support sync invocation`
  - Все узлы агентов переделаны на асинхронные (async/await)
  - Реализован ReAct цикл в `browser_agent_node`
  - MCP инструменты теперь вызываются через `ainvoke()` вместо `invoke()`

- **Реализован полноценный ReAct loop**:
  - Модель → Инструменты → Модель (до 10 итераций)
  - Реальное выполнение browser_navigate, browser_click, browser_type и др.
  - Детальное логирование каждого шага
  - Обработка ошибок инструментов

### 🔄 Changed

- `planner_node`: sync → async
- `browser_agent_node`: sync (симуляция) → async (реальное выполнение с ReAct)
- `cover_letter_agent_node`: sync → async
- Добавлен импорт `ToolMessage` из langchain_core.messages

### 📝 Documentation

- Добавлен `ASYNC_UPDATE.md` с детальным описанием изменений
- Обновлен `CHANGELOG.md`

## [2.0.0] - 2025-11-07

### 🎉 Major Update: Multi-Agent System

Полная переработка архитектуры с простого агента на мультиагентную систему на базе LangGraph.

### ✨ Added

- **Мультиагентная архитектура** с 4 специализированными агентами:
  - `Supervisor` - главный контроллер, маршрутизация между агентами
  - `Planner` - создание и адаптация плана работы
  - `Browser Agent` - работа с браузером (логин, поиск, отклики)
  - `Cover Letter Agent` - генерация сопроводительных писем

- **StateGraph на базе LangGraph**:
  - Циклическая работа с условными переходами
  - Состояние передается между агентами
  - Автоматическое управление flow

- **Система сохранения истории**:
  - `SessionStorage` класс для работы с сессиями
  - Автоматическое сохранение в JSON (`data/sessions/`)
  - Загрузка истории при следующем запуске
  - Проверка дубликатов вакансий по URL

- **Адаптивное планирование**:
  - Planner анализирует историю предыдущих сессий
  - Адаптирует план на основе успешных паттернов
  - Учитывает статистику откликов

- **Генерация сопроводительных писем**:
  - Cover Letter Agent использует Foundation Model
  - Персонализация под каждую вакансию
  - Использование успешных примеров из истории

- **Конфигурационная система**:
  - `config.example.json` - пример конфигурации
  - `config_loader.py` - утилиты для загрузки конфига
  - Поддержка настроек для LLM, браузера, поиска

- **Детальное логирование**:
  - Логи для каждого агента
  - Визуальные индикаторы (эмодзи) для разных этапов
  - Статистика выполнения

- **Тестирование**:
  - `test_graph.py` - базовые тесты системы
  - Проверка импортов, создания состояния, сохранения сессий

- **Документация**:
  - `GRAPH_AGENT_README.md` - детальная документация архитектуры
  - Обновленный `README.md` с инструкциями
  - `CHANGELOG.md` - история изменений

### 🔄 Changed

- **agent.py** сохранен для обратной совместимости
- **main.py** полностью переписан для использования графа
- **.gitignore** обновлен (добавлены config.json, data/, hide_me.py)

### 🏗️ Architecture

**До (v1.x):**
```
Simple Agent → LLM → MCP Tools → Browser
```

**После (v2.0):**
```
Supervisor → Planner → Browser Agent → Cover Letter Agent
     ↓                    ↓                    ↓
  Router          History Analysis    LLM Generation
```

### 🎯 Key Features

1. **Циклическая работа**: система обрабатывает несколько вакансий за запуск
2. **История откликов**: все сессии сохраняются для анализа
3. **Избегание дубликатов**: проверка URL в истории
4. **Адаптивность**: план корректируется на основе результатов
5. **Персонализация**: уникальные письма для каждой вакансии

### 📊 Performance

- Скорость обработки: ~1-2 минуты на вакансию
- Рекомендуемый лимит: 5-10 откликов за сессию
- Размер истории: последние 50 сессий
